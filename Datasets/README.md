# Vessel Detection Dataset 

Training data for the MTU-Net vessel detection model. Every scene is a Landsat 8/9
Collection-2 Level-2 scene with hand-labelled vessel polygons. The model input is the
thermal band (ST_B10). The label is a per-pixel mask: vessel, water or land.

The dataset combines three sources into one layout. Every scene, whatever its source,
is stored and processed the same way.

| Region | Folder names | Source | Scenes |
|---|---|---|---|
| International ports | `Hormuz`, `Malacca`, `Qatar`, `Rotterdam`, `Shanghai`, `Singapore` | Landsat 8/9, 2025-2026 | 6 |
| NE USA | `USA_*` | Landsat 8, June 2020 | 4 |
| Mediterranean | `Med_<YYYYMMDD>_<pathrow>` | Landsat 8, Sept 2020 | 13 |

**`scene_catalogue.csv` is the authoritative list.** It has one row per scene with its
region, split, date, path/row, Landsat product ID and vessel count. It is regenerated by
`python Scripts/data/pipeline_config.py`.

## Folder layout

```
Datasets/
├── README.md                    this file
├── scene_catalogue.csv          one row per scene (region, split, date, vessels ...)
├── Full_Scenes/<Scene>/         RAW INPUTS - the only thing you edit by hand
│   ├── <product>_ST_B10.TIF       thermal band (model input)
│   ├── <product>_QA_PIXEL.TIF     Landsat quality band (fill pixels are masked)
│   ├── <product>_MTL.txt          Landsat metadata (ST_B10 scale/offset)
│   ├── RGB.tif                    optical red/green/blue, native uint16 (not used yet)
│   ├── Land Maps/*.tif            OSM Water Layer 5° tiles covering the scene
│   ├── Shapefiles/*.gpkg          hand-labelled vessel polygons (the labels)
│   └── AIS/*.gpkg                 AIS positions, context only (Mediterranean scenes)
├── Processed_Scenes/<Scene>/    GENERATED by steps 1.0-1.1 (do not edit)
│   ├── <product>_ST_B10_norm.tif  thermal, WGS84, scaled to uint8 (0 = land/fill)
│   ├── <product>_ST_B10_normparams.json
│   └── <Scene>_mask.tif           label raster on the same grid
└── Tiled_Inputs/                GENERATED by step 1.2 - WHAT THE MODEL READS
    ├── Train/<Scene>/Tiles + Labels         512x512 tiles
    ├── Train_CRRP/<Scene>/Tiles + Labels    synthetic copy-paste tiles (only if USE_CRRP is True)
    ├── Validation/<Scene>/Tiles + Labels
    ├── Test/<Scene>/Tiles + Labels
    ├── manifest.csv                         one row per tile (ships, water fraction)
    └── dataset_summary.csv                  tiles and ships per split and scene
```

A tile and its label have the same filename in `Tiles/` and `Labels/`.

## Label encoding (`Labels/*.tif`, uint8)

| Value | Meaning | Used in loss |
|---|---|---|
| 0 | water (no vessel) | yes |
| 255 | vessel | yes |
| 1 | land or no data | no, ignored |

Some polygons carry a `Class` field from the AI4COPSEC project. This dataset ignores the field and treats every polygon as "vessel".

## Splits

Splits are set in one place: `SPLITS` in `Scripts/data/pipeline_config.py`. Folder names
under `Tiled_Inputs/` follow from it. Never move tiles between split folders by hand.

Splits are made **by scene**, never by tile, so no part of a test scene is seen in
training. Scenes whose footprints overlap always share a split, and the largest scenes
train so that no single scene dominates Validation or Test:

- **Train:** Singapore, Shanghai, the NE USA coast (`USA_June13_*`, `USA_June29`) and the
  Aegean and Sea of Marmara (`Med_20200901_*`, `Med_20200903_180032`, `Med_20200910_181032`).
- **Validation:** Rotterdam, south-west Turkey (`Med_20200903_180034`), and Cyprus and the
  Levant (`Med_20200907_176034/176035`, `Med_20200909_174035/174036`).
- **Test:** the Gulf (`Hormuz`, `Qatar`), `Malacca`, the Great Lakes (`USA_June09`), the Suez
  approach (`Med_20200907_176038/176039`) and the Adriatic (`Med_20200909_190030`).

See `scene_catalogue.csv` for every scene's split.

## Rebuilding the data

Run from `Scripts/data/` inside the activated conda environment:

```
conda activate IHVesselDetection
python pipeline_config.py                         # check every scene's inputs, write the catalogue
python run_data_pipeline.py                       # full rebuild, all scenes 
python run_data_pipeline.py --scenes <Scene> ...  # only some scenes
python run_data_pipeline.py --steps 1.2           # re-tile only, after changing SPLITS
```

Activate the environment first. 

## Training and evaluation

Run from `Scripts/training/`. Both scripts read the scene lists from `SPLITS`.

```
python train.py --epochs 300 --batch_size 4
python evaluate.py --checkpoint checkpoints/best.pth --split Test
```

The top-level `README.md` lists every metric and output file.

## Adding a new scene

1. Create `Full_Scenes/<Scene>/` with the files listed above. The ST_B10, QA_PIXEL
   and MTL files must share the same Landsat product prefix.
2. Add `<Scene>` to one split in `SPLITS` in `pipeline_config.py`.
3. Run `python pipeline_config.py`. It names any file that is missing.
4. Run `python run_data_pipeline.py --scenes <Scene>`.

## Sources and licences

- Imagery: Landsat 8/9 Collection-2 Level-2, USGS. Mediterranean scenes were downloaded
  through Microsoft Planetary Computer.
- Land mask: OSM Water Layer (Yamazaki Lab, University of Tokyo), CC BY 4.0. Classes 1-3
  (ocean, large lake/river, major river) count as water.
- Vessel labels: hand-labelled from the imagery. In the Mediterranean, AIS helped confirm
  vessels, but a vessel with no AIS match is still labelled.
